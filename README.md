把哈希换成新算法之后，老客户端仍能拿旧算法签名通过校验，降级攻击直接生效：套件解析把密钥长度存成字符串，强度比较按字典序而不是数值；强度评分对未知算法返回零，未知算法被当成最弱可用项；协商取第一个交集而不是最强交集，客户端顺序决定结果；协商不校验最低强度，弱套件可被选中；封套不写版本，跨版本兼容时字段含义漂移；解封套信任封套内声明的套件而不与策略校验；解封套遇到未知套件返回默认套件，静默降级；密钥绑定只比较长度上限而不比较下限；策略校验不检查是否允许未知算法；批量协商复用交集结果，第二个连接沿用第一个连接的套件。agility/negotiate.py 是核心，tests/unit/test_negotiate.py 15个红。要修的是：按上面的顺序把 10 个缺陷逐个修掉。

初始状态必须恰好是 15 failed，且没有 error。只能修改 `agility/negotiate.py`，不要修改 tests。

## 数据约定

- 套件文本格式为 `hash:signature:bits`，例如 `sha256:rsa:2048`。
- 策略字段为 `min_strength`、`allow_unknown`、`require_key_binding`。
- 密钥字段为 `algorithm`、`bits`。
- 封套必须携带整数版本号，当前版本为 1。
- 强度评分是整数，只允许已知哈希和签名算法参与协商。
